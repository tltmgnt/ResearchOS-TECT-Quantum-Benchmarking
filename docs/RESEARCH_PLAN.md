# QBI-aligned research plan

The independent ResearchOS TECT workspace provides benchmark records and auditable calculations that can support evaluation discussions. It is not a submitted QBIT proposal, a QBI performer, or an independent government validation service.

| Stage | Deliverable | Acceptance evidence | Status |
| --- | --- | --- | --- |
| Workflow foundation | Ideal benchmark, declared resource accounting, evidence capture, verification and reports | Tests, packaged CLI and synthetic bundle | Implemented |
| Workload definition | Application instance, useful output tolerance, classical reference and timing boundary | Reviewed problem specification and baseline reproducibility | Planned |
| Architecture-specific resources | Error model, code/decoder/compiler assumptions, factory/routing and scheduling overhead | Independent reference benchmarks and parameter validation | Not implemented |
| Hardware acquisition | Calibrated device runs, raw counts, repeatability and uncertainty | Acquisition records and original evidence files | No hardware connection/data |
| End-to-end comparison | Matched problem instance, quality, workload count and timing scope | Repeated classical/quantum measurements and review | Not measured |
| Utility assessment | Value, full operating cost, uncertainty and feasibility risks | Application-specific economic/scientific assessment | Not implemented |

## Next gate

Select a real application, justify its output quality criterion, reproduce a strong classical baseline and identify a qualified hardware/architecture partner. Add an independently checked fault-tolerant resource model before treating coarse overhead arithmetic as an architecture estimate. Record all workload correspondence and omissions.

Current demos should be presented as software workflow demonstrations only. Check the applicable QBIT and amendments for scope, eligibility, deadlines and submission instructions. The parent program announcement does not by itself define a submission opportunity for this repository.
